## 一、核心问题

### 词袋模型的致命缺陷

回顾第一课，词袋模型有三大问题：

1. **无法理解语义**
   - "喜欢"和"爱"被当成完全不同的词
   - "苹果"和"香蕉"相似度为0

2. **维度爆炸**
   - 词汇表10万词 → 10万维向量
   - 大部分维度是0（稀疏）

3. **无法泛化**
   - 遇到新词无法处理
   - 无法跨语言

**核心问题**：如何让计算机理解语义？

## 二、分布式假设（理论基础）

### 2.1 核心思想

**"You shall know a word by the company it keeps"**
（通过一个词的"朋友圈"，你就能了解这个词）

### 2.2 直观理解

假设你是外星人，第一次学习人类语言：

```
句子1: 我喜欢吃苹果
句子2: 我喜欢吃香蕉
句子3: 我喜欢吃橙子
句子4: 苹果很甜
句子5: 香蕉很甜
句子6: 橙子很甜
```

**观察**：
- "苹果"、"香蕉"、"橙子"经常出现在相同位置
- 它们前面都是"吃"，后面都是"甜"
- 它们的"上下文"（context）高度相似

**推论**：
即使不知道它们是什么，也能推断：**它们应该是同一类东西**

### 2.3 数学化表示

**上下文窗口**：
```
句子: 我 喜欢 吃 [苹果] 很 甜
上下文: [我, 喜欢, 吃, 很, 甜]
中心词: 苹果
```

**统计规律**：
- "苹果"的上下文：{吃, 喜欢, 很, 甜, ...}
- "香蕉"的上下文：{吃, 喜欢, 很, 甜, ...}
- 上下文重合度高 → 语义相似

### 2.4 关键洞察

**传统方法**：人工定义"苹果"和"香蕉"是水果
**词嵌入方法**：让机器通过大量文本自动发现这种关系

## 三、Word2Vec 训练原理

### 3.1 两种训练方法

#### CBOW (Continuous Bag of Words)
**目标**：用上下文预测中心词

```
输入: [我, 喜欢, 吃, ___, 很, 甜]
输出: 苹果 (或 香蕉、橙子)
```

**训练过程**：
1. 神经网络学习：什么样的词会出现在"吃"和"甜"之间
2. "苹果"、"香蕉"、"橙子"都能被这个上下文预测
3. 因此它们的向量会被调整得越来越接近

#### Skip-gram
**目标**：用中心词预测上下文

```
输入: 苹果
输出: [吃, 甜, 喜欢, ...]
```

**训练过程**：
1. 神经网络学习："苹果"周围会出现什么词
2. "香蕉"周围也会出现类似的词
3. 因此它们的向量会接近

### 3.2 训练目标的数学表示

**Skip-gram 的目标函数**：
```
最大化: P(上下文 | 中心词)
```

例如：
```
P(吃 | 苹果) × P(甜 | 苹果) × P(喜欢 | 苹果) → 最大化
```

**关键**：
- 如果"苹果"和"香蕉"能预测相同的上下文
- 那么它们的向量就会接近

### 3.3 向量的含义

训练完成后，每个词得到一个向量（如300维）：

```
苹果 → [0.2, -0.5, 0.8, ..., 0.3]  (300个数字)
香蕉 → [0.3, -0.4, 0.7, ..., 0.4]  (300个数字)
汽车 → [-0.8, 0.9, -0.2, ..., -0.6] (300个数字)
```

**每个维度的含义**（虽然我们不知道具体是什么）：
- 某些维度可能表示"是否可食用"
- 某些维度可能表示"味道"
- 某些维度可能表示"颜色"
- 某些维度可能表示"大小"

**神奇之处**：这些维度是神经网络自动学习的，不是人工设计的！

## 四、词嵌入的神奇特性

### 4.1 向量运算具有语义

最著名的例子：
```
King - Man + Woman ≈ Queen
```

用向量表示：
```
vec(国王) - vec(男人) + vec(女人) ≈ vec(女王)
```

**为什么会这样？**
- vec(国王) - vec(男人) ≈ "去掉性别的王位概念"
- 加上 vec(女人) ≈ "女性的王位"
- 结果最接近 vec(女王)

类似的例子：
```
Paris - France + Italy ≈ Rome
Tokyo - Japan + China ≈ Beijing
```

### 4.2 语义相似度

```
cos_sim(苹果, 香蕉) ≈ 0.75  (高)
cos_sim(苹果, 汽车) ≈ 0.15  (低)
cos_sim(喜欢, 爱) ≈ 0.85    (高)
cos_sim(喜欢, 讨厌) ≈ 0.30  (低)
```

## 五、从 Word2Vec 到现代模型

### 5.1 技术演进

| 模型 | 年份 | 特点 | 局限 |
|------|------|------|------|
| Word2Vec | 2013 | 每个词固定向量 | 无法处理一词多义 |
| GloVe | 2014 | 基于全局统计 | 同样无法处理一词多义 |
| ELMo | 2018 | 上下文相关 | 计算慢 |
| BERT | 2018 | 双向上下文 | 需要微调 |
| Sentence-BERT | 2019 | 句子级嵌入 | 专为检索优化 |

### 5.2 一词多义问题

**Word2Vec 的问题**：
```
"苹果"在所有句子中都是同一个向量：
- "我吃苹果" → vec(苹果) = [0.2, -0.5, ...]
- "苹果发布会" → vec(苹果) = [0.2, -0.5, ...]  (相同！)
```

**BERT 的改进**：
```
"苹果"的向量取决于上下文：
- "我吃苹果" → vec(苹果) = [0.2, -0.5, ...]  (水果)
- "苹果发布会" → vec(苹果) = [0.8, 0.3, ...]  (公司)
```

### 5.3 Sentence Transformers（我们使用的模型）

**特点**：
1. **句子级编码**：直接对整个句子生成向量
2. **专为检索优化**：训练目标就是让相似句子靠近
3. **多语言支持**：支持50+种语言
4. **高效**：一次编码，可以重复使用

**训练方法**：
- 使用句子对（相似/不相似）训练
- 让相似句子的向量接近
- 让不相似句子的向量远离

## 六、多语言嵌入原理

### 6.1 核心问题

**如何让模型知道中文"苹果"和英文"apple"是同一个意思？**

### 6.2 训练方法

#### 方法1：平行语料（Parallel Corpus）

使用大量翻译对训练：
```
中文: 我喜欢吃苹果
英文: I like eating apples
标签: 这两句是翻译对
```

**训练目标**：
- 让翻译对的向量尽可能接近
- 通过大量翻译对（数百万对），模型学会对齐

**数据来源**：
- 联合国文档（6种官方语言）
- 维基百科（多语言版本）
- 欧洲议会文档
- 电影字幕

#### 方法2：共享词汇空间

**传统方法**：
```
[中文空间]          [英文空间]
  苹果               apple
  香蕉               banana
```
两个独立的空间，无法对比

**多语言嵌入**：
```
[统一的语义空间]
  苹果/apple (同一位置)
  香蕉/banana (同一位置)
```
所有语言共享同一个向量空间

### 6.3 为什么能工作？

**关键洞察**：不同语言的语义结构是相似的

例如，向量运算在不同语言中都成立：
```
中文: 国王 - 男人 + 女人 ≈ 女王
英文: King - Man + Woman ≈ Queen
```

这种结构相似性让多语言对齐成为可能。

### 6.4 实际效果

```
中文查询: "什么是机器学习？"
英文文档: "Machine learning is a subset of AI"
相似度: 0.80 (高！)
```

**应用场景**：
- 跨语言搜索
- 多语言客服
- 零样本翻译

## 七、维度的选择

### 7.1 为什么是300-1000维？

**太少（如10维）**：
- ❌ 无法表达复杂语义
- ❌ 不同概念会混在一起
- 例如：无法同时表示"水果"、"颜色"、"味道"

**刚好（300-1000维）**：
- ✅ 足够表达复杂语义
- ✅ 计算效率可接受
- ✅ 不容易过拟合

**太多（如10000维）**：
- ❌ 浪费计算资源
- ❌ 容易过拟合（记住训练数据，泛化差）
- ❌ 存储成本高

### 7.2 常见模型的维度

| 模型 | 维度 | 用途 |
|------|------|------|
| Word2Vec | 300 | 词级别 |
| GloVe | 300 | 词级别 |
| BERT-base | 768 | 句子级别 |
| BERT-large | 1024 | 句子级别（更强） |
| 本项目模型 | 384 | 句子级别（轻量） |

## 八、总结对比

### 词袋模型 vs 词嵌入

| 特性 | 词袋模型 | 词嵌入 |
|------|---------|--------|
| **原理** | 词频统计 | 上下文学习 |
| **维度** | 词汇表大小（10万+） | 固定（300-1000） |
| **稀疏性** | 稀疏（大部分是0） | 稠密（每维都有值） |
| **语义理解** | ❌ 无 | ✅ 有 |
| **近义词** | ❌ 不识别 | ✅ 识别 |
| **一词多义** | ❌ 无法处理 | ✅ 可以（BERT） |
| **新词** | ❌ 无法处理 | ✅ 可以（子词） |
| **跨语言** | ❌ 不支持 | ✅ 支持 |
| **训练** | 不需要 | 需要大量数据 |

## 九、思考题

在运行实验脚本之前，请先思考：

**问题1**：为什么"苹果"和"香蕉"的上下文会相似？
- 提示：想想它们在真实文本中如何被使用
答：因为苹果和香蕉在生活中属于同一类词汇，水果名词，所以在多数使用场景下位置以及上下文高度相似

**问题2**：上下文相似为什么能推导出语义相似？
- 提示：回顾分布式假设
答：根据分布式假设，通过分析真实语境下，词汇的分布位置，推断出相同位置的词汇用途和表达意义是相似的

**问题3**：为什么多语言模型能让中英文相似句子的向量接近？
- 提示：想想平行语料的作用
答：主要有多种方法，首先是在训练时采用多语言对其，以翻译对的形式出现；然后是词汇共享，对单独的词汇有对应的多语言翻译词汇与其对应；最后是单语言多次单独训练，这样相同空间内的词，其实际含义也是类似的；

**问题4**：如果训练数据中"苹果"总是和"手机"一起出现，会发生什么？
- 提示：想想上下文的影响
答：那么苹果这个词汇可能会朝手机相关的词汇靠近，比如三星、华为等，这一类句字的相似度会提高，会被理解为同一类；
