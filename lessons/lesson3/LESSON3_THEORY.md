## 一、核心问题：为什么需要 FAISS？

### 1.1 暴力检索的性能问题

回顾前两课，我们的检索方法是：**逐个计算相似度，找出最高的**。

```mermaid
graph LR
    Q[查询向量] --> C1[计算 vs 文档1]
    Q --> C2[计算 vs 文档2]
    Q --> C3[计算 vs 文档3]
    Q --> C4[...]
    Q --> CN[计算 vs 文档N]
    C1 --> R[排序取 Top-K]
    C2 --> R
    C3 --> R
    C4 --> R
    CN --> R
```

**时间复杂度**：O(n x d)，n=文档数，d=向量维度

| 文档数量 | 维度 | 耗时 | 能用吗？ |
|---------|------|------|---------|
| 1,000 | 384 | 0.01 秒 | 可以 |
| 10,000 | 384 | 0.1 秒 | 勉强 |
| 100,000 | 384 | 1 秒 | 太慢 |
| 1,000,000 | 384 | 10 秒 | 不可用 |

**问题本质**：每次查询都要遍历所有文档，文档越多越慢。

### 1.2 生活类比：找书

```mermaid
graph TB
    subgraph 暴力检索
        direction TB
        S1[从第1本开始] --> S2[逐本翻看]
        S2 --> S3[第2本...]
        S3 --> S4[第3本...]
        S4 --> S5[...翻完所有书]
        S5 --> S6[找到最相关的]
    end

    subgraph 聪明的方法
        direction TB
        A1[先看分区标签] --> A2{什么类别？}
        A2 -->|科技| A3[只找科技区]
        A2 -->|文学| A4[只找文学区]
        A2 -->|历史| A5[只找历史区]
        A3 --> A6[少量书中找到目标]
    end
```

**FAISS 的核心思想就是"图书馆方法"**：
- 把向量空间分成多个区域
- 查询时只搜索最相关的几个区域
- 大幅减少计算量

## 二、精确搜索 vs 近似搜索

在讲具体索引之前，先理解一个关键概念：

```mermaid
graph LR
    subgraph 精确搜索
        E1[遍历所有文档] --> E2[保证找到真正的 Top-10]
        E2 --> E3["准确率: 100%"]
        E3 --> E4["速度: 慢"]
    end

    subgraph 近似搜索
        A1[只搜索部分区域] --> A2[可能漏掉1-2个]
        A2 --> A3["准确率: 95%"]
        A3 --> A4["速度: 快100倍"]
    end
```

**关键洞察**：RAG 场景中，我们要的是"找到大致相关的文档"，不需要100%精确。

举个例子：
- 精确搜索找到的 Top-10：`[文档3, 文档7, 文档12, 文档5, ...]`
- 近似搜索找到的 Top-10：`[文档3, 文档7, 文档15, 文档5, ...]`
- 只有1个不同，但速度快了100倍
- 对 RAG 来说，这完全可以接受

## 三、FAISS 的三种核心索引

### 3.1 IndexFlatL2 —— 精确但慢

**原理**：就是暴力搜索，计算所有向量的 L2 距离。

```mermaid
graph TD
    Q["查询向量 Q"] --> ALL["逐个比较全部向量"]
    ALL --> D1["距离: 0.5"]
    ALL --> D2["距离: 1.2"]
    ALL --> D3["距离: 0.3 (最近!)"]
    ALL --> D4["距离: 0.8"]
    ALL --> DN["..."]
    D3 --> R["返回最近的 K 个"]

    style D3 fill:#90EE90
```

**特点一句话总结**：最准但最慢，适合文档少的时候。

| 优点 | 缺点 |
|-----|------|
| 100%准确 | O(n)线性扫描 |
| 不需要训练 | 文档多了就慢 |
| 实现简单 | 无法扩展 |

**适用**：文档数 < 10万，或者作为基准测试。

---

### 3.2 IndexIVFFlat —— 分区检索（重点理解）

这是最常用的索引，核心思想是**"先分区，再搜索"**。

#### 训练阶段：把空间分成 nlist 个区

想象一个二维平面上散布着很多点（文档向量）：

```mermaid
graph TD
    subgraph "训练前 - 所有向量混在一起"
        P1((向量)) ~~~ P2((向量))
        P2 ~~~ P3((向量))
        P3 ~~~ P4((向量))
        P4 ~~~ P5((向量))
    end

    subgraph "训练后 - 分成了多个区域"
        direction TB
        C1["区域1 (质心)"] --- V1((向量))
        C1 --- V2((向量))
        C1 --- V3((向量))
        C2["区域2 (质心)"] --- V4((向量))
        C2 --- V5((向量))
        C3["区域3 (质心)"] --- V6((向量))
        C3 --- V7((向量))
        C3 --- V8((向量))
    end
```

训练使用 **K-Means 聚类**算法：
1. 随机选 nlist 个点作为"质心"（区域中心）
2. 每个向量分配到最近的质心
3. 重新计算质心位置
4. 重复2-3步，直到稳定

#### 搜索阶段：只搜索 nprobe 个区

```mermaid
graph TD
    Q["查询向量 Q"] --> FIND["找到 Q 最近的几个区域"]
    FIND --> R1["区域1 (最近)"]
    FIND --> R2["区域2 (次近)"]
    FIND --> R3["区域3 (跳过)"]
    FIND --> R4["区域4 (跳过)"]

    R1 --> SEARCH["只在这2个区域内搜索"]
    R2 --> SEARCH
    SEARCH --> RESULT["返回 Top-K"]

    style R3 fill:#FFB6C1
    style R4 fill:#FFB6C1
    style R1 fill:#90EE90
    style R2 fill:#90EE90
```

**为什么快了？**
- 假设 100万文档，分成 1000 个区（nlist=1000）
- 每个区平均 1000 个文档
- 搜索 10 个区（nprobe=10）：只需比较 10,000 个文档
- 比暴力搜索少了 **100倍** 计算量！

#### 两个关键参数

```mermaid
graph LR
    subgraph "nlist - 分几个区"
        NL1["太小 (10个区)"] --> NL1R["每区太大，还是慢"]
        NL2["刚好 (√n 个区)"] --> NL2R["平衡"]
        NL3["太大 (10000个区)"] --> NL3R["找区本身就慢"]
    end

    subgraph "nprobe - 搜几个区"
        NP1["太小 (1个区)"] --> NP1R["漏掉很多，准确率低"]
        NP2["适中 (10-50个区)"] --> NP2R["平衡"]
        NP3["太大 (=nlist)"] --> NP3R["等于暴力搜索了"]
    end
```

**经验公式**：
- `nlist` = √n（n 是文档数量）
  - 10万文档 → nlist ≈ 316
  - 100万文档 → nlist ≈ 1000
- `nprobe` = 10~50（根据准确率需求调整）

### 3.3 IndexHNSW —— 层次图（最快）

HNSW 的思想完全不同，它构建了一个**多层的图**结构。

#### 类比：地图导航

```mermaid
graph TD
    subgraph "第3层 - 高速公路 - 节点少，跨度大"
        H1((A)) ---|远距离连接| H2((B))
        H2 ---|远距离连接| H3((C))
    end

    subgraph "第2层 - 省道 - 节点适中"
        M1((A)) --- M2((D))
        M2 --- M3((B))
        M3 --- M4((E))
        M4 --- M5((C))
    end

    subgraph "第1层 - 乡道 - 所有节点，精细连接"
        L1((A)) --- L2((F))
        L2 --- L3((D))
        L3 --- L4((G))
        L4 --- L5((B))
        L5 --- L6((H))
        L6 --- L7((E))
        L7 --- L8((I))
        L8 --- L9((C))
    end

    H1 -.-> M1
    H2 -.-> M3
    H3 -.-> M5
    M1 -.-> L1
    M2 -.-> L3
    M3 -.-> L5
    M4 -.-> L7
    M5 -.-> L9
```

#### 搜索过程

```mermaid
graph TD
    START["开始搜索"] --> L3["第3层：快速跳转到大致区域"]
    L3 --> L2["第2层：缩小范围"]
    L2 --> L1["第1层：精确找到最近邻"]
    L1 --> RESULT["返回结果"]

    style L3 fill:#FFE4B5
    style L2 fill:#87CEEB
    style L1 fill:#90EE90
```

**为什么快？**
- 高层：节点少，一步跳很远，快速接近目标
- 低层：节点多，步子小，精确定位
- 类似于"先坐高铁到城市，再坐地铁到街道，最后步行到门口"

| 参数 | 含义 | 经验值 |
|------|------|--------|
| M | 每个节点的连接数 | 16-64 |
| efConstruction | 构建时搜索范围 | 200-500 |
| efSearch | 查询时搜索范围 | 50-200 |

## 四、距离度量：L2 vs 余弦相似度

### 4.1 两种距离的区别

```mermaid
graph LR
    subgraph "L2 距离 - 欧氏距离"
        direction TB
        L2D["测量两点间的直线距离"]
        L2F["d = √(x1-y1)² + (x2-y2)² + ..."]
        L2N["值越小 = 越相似"]
    end

    subgraph "余弦相似度"
        direction TB
        COS["测量两个向量的夹角"]
        COSF["cos θ = A·B / (|A| x |B|)"]
        COSN["值越大 = 越相似（注意方向相反）"]
    end
```

### 4.2 为什么 FAISS 默认用 L2？

1. **计算更快**：不需要额外做归一化
2. **可以等价转换**：向量归一化后，L2 距离和余弦距离效果一样

```mermaid
graph TD
    RAW["原始向量"] --> NORM["归一化（长度=1）"]
    NORM --> EQ["此时 L2距离 ≈ 余弦距离"]
    EQ --> USE["用 FAISS 的 L2 索引就等于在做余弦相似度检索"]
```

**实践做法**：先归一化，再用 IndexFlatL2，效果等同于余弦相似度。

## 六、常见陷阱

### 陷阱1：忘记归一化

```mermaid
graph LR
    WRONG["直接存入 FAISS - 没有归一化"] --> BAD["长向量距离天然更大 - 结果不准确"]
    RIGHT["先归一化再存入"] --> GOOD["L2 距离 = 余弦距离 - 结果正确"]

    style WRONG fill:#FFB6C1
    style RIGHT fill:#90EE90
```

### 陷阱2：IVF 训练数据不够

训练数据至少需要 `nlist x 39` 个向量，否则聚类质量差。

### 陷阱3：nprobe 太小

`nprobe=1` 只搜索1个区域，准确率可能只有 60-70%，漏掉大量相关文档。

### 陷阱4：没有保存索引

构建索引很耗时，一定要 `faiss.write_index()` 保存到磁盘。
